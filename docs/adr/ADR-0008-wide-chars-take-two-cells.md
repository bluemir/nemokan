# ADR-0008: 전각 문자는 두 칸으로 계산한다

## Status

Accepted

## Date

2026-10-25

## Context

원본 MonoSketch 는 모든 문자를 한 칸으로 계산한다. 한글, 한자 같은 전각 문자는 화면에서 두 칸 너비로 그려져서 옆 글자와 겹친다. 텍스트로 내보내도 줄이 맞지 않는다.

한글과 전각, 반각 처리는 이 프로젝트를 만드는 이유 중 하나다.

정해야 할 것은 다음과 같다.

- 어떤 문자를 두 칸으로 볼지
- 두 칸 중 두 번째 칸을 보드에 어떻게 나타낼지
- 다른 도형에 가려 두 칸 중 한 칸만 남았을 때 어떻게 그릴지

## Decision

**Unicode East Asian Width 가 Wide(W) 또는 Fullwidth(F) 인 문자는 두 칸으로 계산한다.**

- 한글, 한자, 가나, 전각 기호, 대부분의 emoji 가 해당한다.
- Ambiguous(A) 문자(`○`, `■`, `▶` 등)는 한 칸으로 둔다. 원본의 선 끝 모양과 채우기 스타일 중 Ambiguous 문자가 많아서, 두 칸으로 바꾸면 기존 그림 모양이 깨진다.
- 판별은 `golang.org/x/text/width` 로 한다.

**두 번째 칸은 `bitmap.WideCharTail` 로 표시한다.**

- 투명하지 않아서 아래에 있는 도형을 가린다.
- 문자열로 바꿀 때(`String`, 내보내기)는 빠진다. 그래서 "안녕" 은 네 칸을 차지하지만 문자열로는 "안녕" 이 된다.
- JS 에 넘기는 보드에서는 `"\0"` 으로 넘긴다. JS 는 다음 칸이 `"\0"` 인 문자를 두 칸 너비로 그린다.
- 첫 칸만 남고 두 번째 칸이 다른 도형에 가려지면 첫 칸의 문자도 그리지 않는다. 두 칸 너비 글자가 위 도형을 덮는 것을 막기 위해서다.

**텍스트 줄바꿈과 크기는 칸 수로 계산한다.** 전각 문자는 쪼개지 않는다.

## Consequences

- 원본과 달리 한글 텍스트의 크기와 줄바꿈이 화면과 맞는다.
- 글꼴의 전각 문자 폭이 정확히 두 칸이 아니어도 JS 가 두 칸에 맞춰 그린다.
- 결합 문자(조합형 한글 자모, 악센트 결합 문자)는 따로 다루지 않고 한 칸으로 본다. 필요해지면 다시 정한다.
