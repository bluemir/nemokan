# ADR-0014: UI 요소는 Widget 도형 하나와 종류별 내용으로 만든다

## Status

Accepted

## Date

2026-11-02

## Context

Mockdown 의 UI 요소 19가지(버튼, 입력칸, 카드, 표, 모달, 체크박스, 라디오, 드롭다운, 토글, 탭, 검색, 진행 막대, 경로, 페이지 번호, 내비게이션, 목록, 빈 칸 표시, 좌우 나누기, 이미지 칸)를 새 도형 종류로 넣기로 했다. 정한 것은 다음과 같다.

- 표시 기호는 ASCII 다. `[x]`, `(o)`, `[v]` 처럼 쓴다. ☑ ● ▾ 같은 기호는 유니코드 폭이 애매해서, D2Coding 같은 한글 글꼴이나 한글 터미널에서 2칸으로 그려져 줄이 어긋난다.
- 테두리가 있는 요소는 사각형처럼 테두리 모양과 채우기를 고른다.
- 한 줄짜리 요소는 폭만 바꾼다. 체크박스, 라디오, 토글, 경로, 페이지 번호는 내용 크기를 따른다.
- 도구 막대에 19가지를 모두 보인다.
- 내용은 속성 패널과 캔버스 더블클릭 둘 다에서 고친다. 더블클릭은 마우스 아래 칸을 고치고, 표시 기호를 더블클릭하면 켜고 끈다.

도형을 어떻게 나눌지는 두 방식을 견주었다.

- 종류마다 `Shape` 구현: 19가지가 모두 bound, 직렬화, 명령, 그리기 분기를 따로 가져서 같은 코드가 19번 되풀이된다.
- `Widget` 도형 하나와 종류별 내용(`WidgetContent`): 도형의 공통 동작은 한 곳에 두고, 종류마다 다른 것(크기 규칙, 보이는 것, 글자 고치기)만 내용이 맡는다.

## Decision

**`shape.Widget` 하나가 모든 UI 요소이고, 종류마다 `WidgetContent` 를 구현한 구조체를 둔다.**

- `WidgetContent` 는 종류(`Kind`), 크기 규칙(`fit`), 보이는 것(`layout`), 글자 고치기(`withText`)를 가진다. 켜고 끄는 종류는 `toggled` 도 가진다.
- `layout` 은 상자 여부, 상자 안의 구분선, 글자 묶음(run)을 돌려준다. 고칠 수 있는 글자 묶음은 어느 칸(`WidgetField`)인지를 가진다.
	- 그리기(`bitmapmanager`)는 layout 대로 그린다. 상자는 사각형과 같은 방식으로, 구분선이 테두리나 다른 구분선과 만나는 곳은 테두리 모양에 맞는 분기 글자(├ ┬ ┼, ┣ ╋, ╠ ╬)로 그린다.
	- 더블클릭은 같은 layout 에서 마우스 아래 칸을 찾는다. 그래서 그리는 것과 고치는 칸이 어긋나지 않는다.
	- 상자가 없는 요소는 bound 전체를 공백으로 채운다. 아래를 가리고, 어디를 눌러도 고를 수 있다.
- 파일에는 `"type": "widget"`, `"kind"`, `"content"`(종류별 구조체의 JSON), `"extra"`(상자의 테두리와 채우기)로 적는다. 모르는 종류나 깨진 내용이 있는 파일은 열지 않는다.
- 속성 패널은 JS 에 종류별 입력 양식(글자, 목록, 체크, 숫자, 목록 중 하나)을 두고, 고친 내용 JSON 을 통째로 보낸다(`changeWidgetContent`). Go 는 그 종류의 구조체로 읽히는 것만 받는다.
- 요소를 더하는 도구는 `Retainable` 에 종류를 담는다(`widget:button`). 클릭하면 기본 크기로, 끌면 종류가 허락하는 만큼 그 크기로 놓는다.
- 캔버스에서 고치는 칸은 한 줄이라 Enter 로 끝난다. 텍스트 편집은 도형 대신 바뀔 때와 끝날 때 할 일을 받도록 바꿨다.

## Consequences

- 새 종류는 `WidgetContent` 구조체 하나와 JS 의 입력 양식 하나로 더한다.
- 내용의 크기 규칙이 bound 를 정하므로, 글자를 고치면 크기가 바뀔 수 있다(체크박스 라벨, 목록 항목 수 등).
- 버튼은 라벨보다 좁아지지 않는다. 드롭다운, 입력칸, 검색, 표, 카드처럼 폭을 정하는 요소는 넘치는 글자를 자른다.
- 이전 버전은 widget 이 든 파일을 열지 못한다.
