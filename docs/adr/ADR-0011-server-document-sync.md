# ADR-0011: 서버 문서 API 와 로컬 문서 동기화

## Status

Accepted

## Date

2026-10-25

## Context

ADR-0002 에서 로컬에 먼저 저장하고 서버와 동기화하기로 했다. 서버 문서의 종류, 권한, revision 충돌은 거기서 정했다.
남은 문제는 다음과 같다.

- 서버 문서를 언제 만들고, 언제 저장하는가
- 로컬 문서(IndexedDB)와 서버 문서를 어떻게 잇는가
- 사본("내 문서로 가져오기", 충돌 시 "사본으로 저장")을 어디서 만드는가
- 문서 ID 를 어떻게 만드는가

## Decision

### 만들기와 저장

- `/edit` 는 계속 로컬 전용이다. 문서 메뉴의 "서버에 올리기"로 현재 문서를 서버 문서로 만들고 `/p/<id>` 로 옮긴다.
- `/p/<id>` 에서 편집하면, 마지막 변경 뒤 2초가 지나면 자동으로 서버에 저장한다. 로컬에는 지금처럼 300ms 뒤에 저장한다 (ADR-0007).
- 익명 문서는 지우는 API 가 없다. 90일 만료로만 사라진다. 소유 문서는 소유자만 지운다.

### API

| 요청 | 하는 일 |
| --- | --- |
| `POST /api/v1/documents` | 문서를 만든다. 로그인했으면 소유 문서(비공개), 아니면 익명 문서 |
| `GET /api/v1/documents/:id` | 문서를 읽고 마지막 접근 시각을 갱신한다 |
| `PUT /api/v1/documents/:id` | 문서를 고친다. 요청의 revision 이 서버와 다르면 `409` |
| `PUT /api/v1/documents/:id/visibility` | 소유자가 공개 범위를 바꾼다 |
| `DELETE /api/v1/documents/:id` | 소유자가 지운다 |
| `GET /api/v1/documents` | 로그인한 사용자의 소유 문서 목록 |

- 내용은 ADR-0004 의 파일 JSON 그대로다. 서버는 Go 의 `shape.ParseFile` 로 읽어 보고, 읽을 수 없으면 받지 않는다. 문서 이름도 여기서 꺼낸다.
- 고칠 때는 `WHERE id = ? AND revision = ?` 조건으로 한 번에 바꾼다. 바뀐 행이 없으면 충돌이다.
- 비공개 문서를 소유자가 아닌 사람이 읽으면 `404` 다. 문서가 있다는 것도 알리지 않는다.
- 볼 수는 있지만 고칠 수 없으면 `403` 이다. `GET` 응답의 `canEdit` 로 편집기가 미리 안다.
- 크기 제한(기본 1MiB)과 IP 별 생성 횟수 제한(기본 시간당 30개)은 grim 과 같은 방식(GCRA, IPv6 는 /64 단위)이다. 제한은 생성에만 건다.
- 마지막 접근 뒤 보존 기간(기본 90일)이 지난 익명 문서는 서버가 한 시간마다 지운다.

### 문서 ID

- 영문 대소문자 16자를 `crypto/rand` 로 만든다 (약 91비트).
- 익명 문서는 URL 이 곧 권한이라 추측할 수 없어야 한다. 템플릿이 쓰는 xid 는 시각과 카운터로 만들어 이웃 ID 를 짐작할 수 있어서 쓰지 않는다.

### 로컬 문서와 잇기

- 로컬 문서 레코드에 `serverId`, `revision`(로컬 내용의 바탕이 된 서버 revision), `syncedAt`(마지막으로 서버와 맞춘 시각)을 더한다.
- 로컬이 서버에 아직 보내지 않은 변경을 가졌는지는 `updatedAt > syncedAt` 으로 안다.
- `/p/<id>` 를 열 때
	- 같은 `serverId` 의 로컬 문서가 없으면 서버 내용으로 로컬 문서를 만든다.
	- revision 이 같으면 로컬 내용을 연다. 보내지 않은 변경이 있으면 이어서 저장한다.
	- 서버가 더 새롭고 로컬에 보내지 않은 변경이 없으면 서버 내용을 받는다.
	- 서버가 더 새롭고 로컬에도 보내지 않은 변경이 있으면 충돌 dialog 를 띄운다.
	- 서버에 닿지 않으면 로컬 내용을 연다.

### 사본

- 사본은 브라우저에서 만든다. Go 가 지금 문서를 열어 둔 채 새 root ID 의 사본 내용을 만들고, `POST` 로 새 문서를 만든다.
- 사본은 서버에 만든 뒤에만 그 페이지로 옮겨 연다. 만들지 못하면 실패를 알리고 원래 문서에 머문다. 읽기 전용 문서였으면 읽기 전용 그대로다.
- 그래서 "내 문서로 가져오기"와 충돌 시 "사본으로 저장"은 같은 동작이고, 서버에 사본 API 를 두지 않는다.
- 새 root ID 를 쓰는 까닭은 로컬 문서가 root ID 로 저장되기 때문이다. 같은 root ID 를 쓰면 원본 문서의 로컬 문서와 겹친다.

## Consequences

- 서버는 도형 형식을 알아야 해서 `internal/shape` 를 import 한다. 대신 깨진 내용이 저장되지 않는다.
- 자동 저장이라 2초마다 쓰기 요청이 생길 수 있다. 크기 제한 안에서는 받아들인다.
- 읽기만 해도 DB 쓰기가 생긴다 (ADR-0002).
- 같은 문서를 두 탭에서 동시에 고치면 한쪽이 충돌 dialog 를 본다.
- 읽기 전용 문서는 서버에 저장하지 않고 사본 만들기를 권한다. 편집 자체는 ADR-0012 에서 Go 엔진이 막는다.
