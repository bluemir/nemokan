# ADR-0002: 로컬에 먼저 저장하고 서버와 동기화한다

## Status

Accepted

## Date

2026-10-25

## Context

이 문서들에서 "문서"(document)는 그림 한 장을 말한다. 원본 MonoSketch 는 이것을 project 라고 부른다. 여러 문서를 묶는 단위는 없다.

원본 MonoSketch 는 브라우저 localStorage 에만 저장한다. 그래서 다른 기기에서 열거나 남에게 공유할 수 없다.

`~/src/bluemir/grim` 은 서버에 익명으로 저장한다. 다만 저장된 다이어그램은 내용 해시로 ID 를 만드는 불변 스냅샷이다.
편집기에서는 같은 도면을 계속 고치므로, 같은 URL 의 내용을 덮어쓸 수 있어야 한다.

## Decision

**브라우저에 먼저 저장하고, 서버에는 내용을 바꿀 수 있는 문서로 동기화한다.**

### 로컬

- 모든 편집은 먼저 브라우저(IndexedDB)에 저장한다.
- 로그인 없이도 로컬 저장만으로 편집기를 쓸 수 있다.

### 서버 문서

서버 문서는 익명 문서와 소유 문서 두 종류다. URL 은 둘 다 `/p/<id>` 다.

- 익명 문서
	- 인증 없이 만들 수 있다.
	- URL 을 아는 사람은 누구나 보고 수정할 수 있다. 편집 토큰은 두지 않는다.
- 소유 문서
	- 로그인한 상태에서 새로 만든 문서는 처음부터 소유 문서다.
	- 로그인한 사용자가 익명 문서를 "내 문서"로 가져오면 새 ID 의 사본이 소유 문서가 된다.
	- 원본 익명 문서는 그대로 남는다. 그래서 같은 URL 을 공유받은 다른 사람이 쫓겨나지 않는다.
	- 소유자는 공개 범위를 고른다: 비공개, 누구나 보기, 누구나 편집. 기본값은 비공개다.
	- 소유자가 아닌 사람이 편집할 수 없는 문서를 고치려면 사본을 만든다.
- grim 처럼 크기 제한과 IP 별 생성 횟수 제한을 둔다.

익명 문서에 편집 토큰을 두는 방식(보기 URL 과 편집 URL 분리)도 검토했다.
하지만 익명 문서는 URL 하나로 쉽게 공유하는 쪽이 더 중요하다고 보고, 권한 구분은 소유 문서에서만 하기로 했다.

### 충돌

- 서버 문서에는 revision 번호가 있다.
- 저장할 때 마지막으로 받은 revision 을 함께 보낸다. 서버의 revision 과 다르면 `409 Conflict` 를 돌려준다.
- 충돌하면 `<dialog>` 로 사용자에게 세 가지 중 하나를 고르게 한다.
	- 내 것으로 덮어쓰기
	- 서버 것 받기
	- 사본으로 저장
- 도형 단위 병합은 하지 않는다.

### 만료와 연장

- 익명 문서는 마지막 접근(보기 또는 수정) 후 90일이 지나면 삭제한다. 기간은 config 로 바꿀 수 있다.
- 소유 문서는 만료되지 않는다.
- 로그인은 템플릿의 webauthn 을 쓴다.

## Consequences

- 서버가 없거나 연결이 끊겨도 편집할 수 있다.
- 익명 문서는 URL 이 새면 누구나 고치거나 지울 수 있다. 지금은 버전 기록을 두지 않으므로, 망가지면 각자 로컬(IndexedDB)에 남은 것으로 되살려야 한다.
- 익명 문서로는 읽기 전용 공유를 할 수 없다. 그러려면 로그인해서 소유 문서로 만들어야 한다.
- 소유 문서로 가져오면 ID 가 바뀌므로, 이미 공유한 익명 URL 은 계속 익명 문서를 가리킨다.
- 조회할 때마다 마지막 접근 시각을 갱신하므로 읽기 요청에도 DB 쓰기가 생긴다.
- 충돌을 사용자에게 묻는 방식이라 같은 도면을 동시에 편집하는 협업은 지원하지 않는다.
- 저장 포맷은 원본과 호환하지 않는다. 대신 포맷에 version 을 넣어 이후 마이그레이션에 대비한다.
