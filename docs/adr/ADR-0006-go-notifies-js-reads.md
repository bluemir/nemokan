# ADR-0006: Go 는 바뀐 것을 알리고, JS 는 다음 프레임에 읽어 간다

## Status

Accepted

## Date

2026-10-25

## Context

ADR-0001 과 ADR-0003 에서 두 가지를 미뤄 두었다.

- JS UI 가 Go 의 상태 변경을 어떻게 받을지
- 문자 보드를 canvas 에 그릴 때 전체를 넘길지, 바뀐 영역만 넘길지

원본에서 상태(statemanager)가 UI(canvas, 툴바)에 알리는 것은 다음과 같다.

- 문자 보드 다시 그리기 요청 (도형 변경, 화면 크기 변경, 스크롤)
- 선택 영역, 선택한 도형의 조절 핸들, 마우스 커서
- 툴바 상태 (선택한 도형의 스타일, 편집 모드 등)
- 텍스트 편집 시작

원본은 다시 그리기 요청을 다음 프레임까지 모아 한 번만 그리고, 그릴 때는 화면에 보이는 영역 전체를 칸마다 다시 칠한다. 화면 하나는 보통 1만 칸 남짓이다.

검토한 방식은 다음과 같다.

- 변경 전달
	- Go 가 데이터까지 담아 JS 콜백 호출: 단순하지만, 한 프레임에 여러 번 바뀌면 그만큼 데이터를 만든다.
	- JS 가 매번 다시 읽기: 알림이 없어도 되지만, 바뀌지 않아도 읽는다. 마우스 처리처럼 Go 안에서 생긴 변화를 알 수 없다.
	- Go 가 바뀐 종류만 알리고 JS 가 다음 프레임에 읽기
- 보드 전달
	- 칸마다 JS 가 Go 함수 호출: 한 프레임에 만 번 넘게 경계를 넘는다.
	- 바뀐 영역만: 데이터는 적지만 Go 보드에 바뀐 영역 추적을 새로 넣어야 한다.
	- 화면 영역 전체를 한 번에

## Decision

**Go 는 바뀐 종류만 JS 콜백으로 알리고, JS 는 `requestAnimationFrame` 에서 필요한 데이터를 Go 에서 읽어 간다. 문자 보드는 화면 영역 전체를 한 번에 넘긴다.**

```
Go: 상태 변경 → JS 콜백 ("board", "selection" 같은 종류만)
JS: 다음 프레임에 한 번 → monosketch.board() 등으로 읽어서 그림
```

- 같은 프레임에 같은 알림이 여러 번 와도 JS 는 한 번만 읽는다. 다음 프레임으로 미루는 throttle 은 JS 가 맡으므로 Go 의 `observable` 에는 넣지 않는다.
- 문자 보드는 화면 영역 전체를 줄별 문자열과 칸별 강조 상태 바이트 배열로 넘긴다.
- 알림 종류와 읽기 API 의 이름은 JS 와 WASM 경계를 만들 때 정한다.

## Consequences

- 원본과 같이 매번 화면 전체를 다시 그린다. 느리다고 확인되면 그때 바뀐 영역만 넘기는 방식을 검토한다.
- Go 는 JS 콜백을 하나 이상 가지고 있어야 하므로, JS 가 시작할 때 콜백을 등록한다.
- Go 안의 상태 코드는 JS 없이도 테스트할 수 있다. 알림은 Go 함수로 받는다.
