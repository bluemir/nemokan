# ADR-0012: 읽기 전용 문서는 Go 엔진에서 편집을 막는다

## Status

Accepted

## Date

2026-10-25

## Context

ADR-0011 에서 고칠 수 없는 서버 문서도 편집기에서 열고, 서버에 저장하지만 않기로 했다. 그래서 사용자가 고친 내용이 저장되지 않고 사라진다.

도형을 바꾸는 경로는 여러 곳이다.

- 마우스: 도형 추가, 드래그 이동, 크기 조절, 선 조작, 더블클릭 텍스트 편집
- 단축키와 툴바: 삭제, 이동, 잘라내기, 복제, undo, redo, 도구 선택
- 서식 패널: 스타일, 위치, 크기, 순서
- 붙여넣기

검토한 방식은 다음과 같다.

- JS 에서 막기: 버튼과 단축키를 감추거나 무시한다. 경로마다 따로 막아야 해서 하나를 빠뜨리기 쉽다. 드래그 이동처럼 Go 안에서 정해지는 동작은 JS 가 막을 수 없다.
- Go 엔진에서 막기: 동작, 마우스 명령, 붙여넣기가 모두 Go 의 `state.Manager` 를 지나므로 그곳에서 한 번에 막는다.

## Decision

**`state.Manager` 에 접근 권한(`Access`: edit, view)을 두고, view 에서는 Go 가 도형을 바꾸는 일을 모두 거절한다.**

- view 에서 되는 것
	- 선택 (클릭, 영역 선택, 전체 선택, 선택 해제)
	- 복사, 텍스트로 복사, 텍스트로 내보내기, 파일로 저장
- view 에서 안 되는 것
	- 그 밖의 동작, 붙여넣기, 도형 추가 도구
	- 마우스는 선택 명령만 쓴다. 선택한 도형의 조절 핸들도 그리지 않는다.
- JS 는 서버 응답의 `canEdit` 로 `setAccess` 를 부르고, 편집 도구, undo, redo, 서식 패널, 이름 변경을 감춘다. 감추는 것은 화면 정리일 뿐이고, 막는 것은 Go 가 한다.
- 문서를 여는 일(`restore`, `openFile`, 사본으로 열기)은 동작이 아니므로 view 에서도 된다. 사본을 만들면 새 문서 페이지에서 다시 권한을 정한다.

## Consequences

- 새 동작을 더하면 view 에서 허용할지 `isAllowed` 에서 정해야 한다. 정하지 않으면 막힌다.
- 고칠 수 없는 문서에서 고치려면 사본을 만들어야 한다.
